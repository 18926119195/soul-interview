## 2. 核心方法论（不是术语，是我已经做了 6 年的事）

这一节是简历的方法论核心，也是岗位 1 / 岗位 2 / 岗位 3 的共同底座。每一个论证都能直接对应到代码库里的某个文件。

### 2.1 希尔曼的"召唤（calling / daimon）"理论 → 对应到「灵魂同行者」系统

**理论**：人在出生前已选定自己的 daimon（守护天才 / 生命蓝图）；父母的"错位婚姻"恰恰是为了孕育客户的独特性。**不要让客户去"修复童年创伤"，而要客户去"识别童年里那个猛烈吸引他的东西"**。

**工程化**：
- `autobio-web/src/lib/soul-companion-registry.ts` —— 每个访谈主题匹配一个真实历史人物的"灵魂同行者"（梅纽因、卡内蒂、麦克林托克、马诺雷特、卡什等）。
- `autobio-web/src/lib/companion-name.ts` —— 人名兜底索引；保证故事库走 `companion_init JSON`，前者只作旧数据兜底。
- AI 不是"采访员"，是"以同行者的口吻去探望客户"——"梅纽因童年时曾被一把小提琴的声音击晕，您是否也有过被某个声音/气味彻底击倒的瞬间？"

**面试可引用逻辑**：
- 岗位 1：客户的回忆录不是"挖掘客户已有的人生"，是"创造一次让客户的 daimon 被召唤出来的相遇"。
- 岗位 2：罗曼史 AI 陪伴里的"男主"不是"完美的白马王子"，是"一个有 daimon 的活人"——他要有自己的"生命召唤"，才能真正被读者 / 用户感知为"可以爱上的"。
- 岗位 3：销转对话里的"销冠"也不是"话术机器人"，是"一个有 daimon 的人"——他用自己独特的审美逻辑编织对话，而不是背脚本。

### 2.2 加塔利的"分裂分析制图学（schizoanalytic cartography）" → 对应到「灵魂地图 3D 视图」

**理论**：心理现实不在某个抽象的"自我"内部，在**主体与世界、他者、事物的关系网**上。回忆录不是"客户的人生"，是"客户 + 他者 + 事物"的复调。

**工程化**：
- `autobio-web/src/components/ModuleGraph.tsx` —— 4 隧道 × 2 阶段的 3D 视图
- `autobio-web/src/lib/soul-map-anchors.ts` + `cvs-space.ts` —— 空间坐标与锚点
- `autobio-web/src/components/CompanionConstellation.tsx` —— 同行者星座（他者图层）
- `autobio-web/src/lib/rope/` —— 多 PDF 跨页"绳索"（被事物看见隧道）

**面试可引用逻辑**：
- 岗位 1：灵魂地图 3D 视图不是"立体可视化"（数据可视化），是**分裂分析制图术**——一种"让情动直接转化成生产力"的空间拓扑（参见 p22「情动即生产力」）。
- 岗位 2：罗曼史陪伴产品的"用户情感地图"——不是"用户-角色关系网"这种二维关系图，是 3D 制图空间，让用户能看见"我和男主 + 我身边的他者 + 我喜欢的物品"如何共同构成一段感情。
- 岗位 3：销转对话不是"销售漏斗"，是**对话地图**——客户、销冠、产品、参考案例在同一个 3D 空间里被共同制图。

### 2.3 斯特恩（Daniel Stern）的"生命形式（forms of vitality）" → 对应到「质感提问」技法

**理论**：一个人最重要的不是"是什么"，是**回忆的"质感"**——舒缓的、激烈的、颤抖的、温暖的、不可言说的？这种质感被斯特恩命名为"forms of vitality"——它攻击了以封闭母婴关系为基础的心理学，证明主体性是以某种主动的方式与外部互动调谐。

**工程化**：
- `自传意象技法库.md` —— 完整 17 章"提问技法库"，每条都围绕"质感"展开：
  - 第五章「情感与意象」：情感作为限定词 / 想象情感（"如果把'崩溃'这个词去掉，是哪个具体的画面让你有这种感觉？"）
  - 第九章「意象-词：概念与意象」：特定化名词 / 形容词实体化与反转 / 动词与副词的倒置 / 去字面化
  - 第十章「意象作为感知对象」：联觉感知 / 意象式阅读（slowing down）/ 嗅觉类比
  - 第十四章「小工具：意象机械学」：增厚法 / 渴望法 / 忍受法 / 裂隙法（"你说'但是'的那个瞬间，到底发生了什么变化？"）

**面试可引用逻辑**：
- 岗位 1：访谈脚本的铁律——**用非线性来写，尽量少用名词；一旦遇到不可或缺的名词，回到那个场景去感受里面的质感（形容词、副词、动词）**。
- 岗位 2：罗曼史陪伴产品的关键不是"男主的台词写得有多华丽"，是**用户读到的"质感"**——让用户感觉"我被男主真实地看见了"，而不是"男主背了一段剧本"。这要求对话系统能在用户回应里检测到"质感形容词/副词密度"，并在叙事语言里同等密度地回应。
- 岗位 3：销转对话的可量化指标——**质感仪表盘**（形容词/副词密度 + 身体感觉词密度 + 关键意象反复度）= 0-100 强度评分。强度过低时插入刺激性提问；强度过高时放慢节奏。

### 2.4 "情动即生产力（affect as productivity）" → 对应到 Dify 工作流 + Vercel 部署

**理论**（来自 p22 + p28）：**"以分裂分析制图术以及超文本的概念在一个立体空间中实现剪辑流，这样能够在将情动直接转化成生产力，将症状的心理动力转化为切切实实的生产力"**——回忆录项目交付的不是"一本书"，是**客户的复调关系网的一次显化**。

**工程化**：
- `非线性自传创作 (10).yml` —— Dify 高级工作流（含校验节点、Python 脚本、父子分段索引）
- `autobio-web/src/lib/dify-client.ts` —— Dify 客户端封装
- `autobio-web/src/app/api/chat/route.ts` —— Next.js API 路由
- `docs/DEMO-DEPLOY.md` —— Cloudflare Tunnel + Vercel 零 VPS 部署方案
- `autobio-web/src/lib/glmOcr.ts` + `pdf-cut` 路由 + `pdfjs-dist` + `tesseract.js` —— 多模态 OCR + 语音 + PDF

**面试可引用逻辑**：
- 岗位 1：客户上传旧照片/旧文件 → OCR 提取文字 → 姓名脱敏 → 进入隧道对话 → 自动结构化为块茎章节。
- 岗位 2：用户的语音消息不只是"识别成文字"，是**感受成情动**——音量 / 语速 / 停顿被作为情动强度的辅助信号输入给"男主回应生成器"。
- 岗位 3：销转对话里的客户语音 / 图片 / 截图 → 多模态 OCR → 强度仪表盘 → 实时识别"质感回应" → 决定 AI 接管 / 真人接管。

### 4.2 岗位 ②：海外 AI 虚拟陪伴产品经理——25+ 欧美女性用户（罗曼史 / 互动剧情 / 乙游赛道）

| 罗曼史 AI 陪伴和 Character.ai 的区别是什么？ | Character.ai 的男主是"对话模拟"，我的设计是基于"灵魂同行者"——男主要有自己的 daimon（生命召唤），他要能"看见用户的具体物"，在对话中能回应用户的"质感形容词"——不是"你真漂亮"，是"你刚才说的'突然'这个词让我想到……"。 |
| 怎么让对话不像"AI 在背话术"？ | 我的 17 个提问技法中有 5 个直接可用于罗曼史对话：(1)「去字面化」——"你说'心动'，如果它是一个动作，会是什么？"；(2)「联觉感知」——"那个画面如果有声音，会是什么声音？"；(3)「动词与副词的倒置」——"你说'渴望地看向你'，那如果说'看向地渴望'呢？"；(4)「特定化名词」——"那不是'随便一束花'，是什么样的花？"；(5)「拒绝还原」——"除了'一见钟情'，这件事还有没有别的解释？" |
