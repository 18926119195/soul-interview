## 阅读结果

这份文档是美国专利申请公开 **US 2012/0137202 A1**，标题为 **《SYSTEM FOR EXPLORING CONNECTIONS BETWEEN DATA PAGES》（用于探索数据页面之间连接的系统）**，发明人为 **Theodore Holm Nelson**（超文本概念提出者）。

该文档详细描述了一种名为 **CVS (Connection Visualization System)** 的系统，核心在于如何可视化展示不同文档（Data Pages）之间的 **Transclusion（包含/复用）** 关系及 **Flinks（带位置信息的前向链接）**。

以下是基于该 PDF 证据，结合「非线性自传」产品形态整理的**工程落地把关文档**：

### 〇、概念小注（白话：各自用来干嘛）

| 概念 | 用来干嘛（一句话） |
| :--- | :--- |
| **Data Page（数据页）/ 生命切片** | 装「一段记忆」的容器：一篇回答、一段日记、一张图，都能算一页。没有它，后面没东西可连。 |
| **Transclusion（包含/复用）/ 印记** | 发现「两段话其实是同一段内容的复用或极像」。用来自动揪出跨页重复的记忆片段，而不是靠人手翻。 |
| **Flink（前向链接）/ 隧道** | 记录「从 A 页某一段 → 指到 B 页某一段」，并且记得起止位置、是弱相关还是强引用。用来做可点击、可画线的跨页跳转。 |
| **Connection / Link 16 / 命运线** | 屏幕上那根看得见的连线。用来让用户一眼看出「这两段是挂在一起的」，不只是数据库里有条记录。 |
| **Strand（串）/ 同行者（本组用法）** | 把一堆相关连接捆成一束（比如「都关于童年恐惧」）。用来主题分组、成批展示，避免满屏散线。 |
| **CVS / 灵魂地图** | 整套「把连接画成空间图」的界面。用来浏览全局关系，而不是只在聊天里一条条翻。 |
| **Sweeping（扫视）/ 漂移** | 拖动/转动观察角度。用来把叠在一起的线「拨开」，看清哪条连哪。 |
| **Zooming（缩放）** | 放大某一条连接或某一段文字。用来从「看全貌」切到「看细节」。 |
| **Stand-off（分离视图）** | 两页并排、拉开距离同屏看。用来对照阅读，不被叠在一起挡住。 |
| **Overlay（叠加视图）** | 一页半透明盖在另一页上。用来感受「同一位置上的重叠/呼应」。 |
| **Span（跨度）** | 连线不是点对点，而是「整段文字区域」对「整段」。用来高亮真实引用范围，而不是只标一个字。 |
| **Corner-points（角点）** | 画弯线用的控制点。用来让连线绕开、散开，少糊成一团。 |
| **Current Page（当前页）** | 你正在看的那一页，视觉锚点。用来当「此刻」的参照系。 |
| **Arrival Page（到达页）** | 连线指向的另一页。用来展示「从这里跳过去会落到哪」。 |
| **Disagreement / 悖论** | 标记两段记忆互相打架（开心 vs 痛苦）。用来显式标矛盾，而不是假装一切自洽。 |
| **Permascroll（永久地址）** | 给文本位置一个稳定坐标（第几段第几个字）。用来保证「连线对准的地方」以后还能找回来。 |
| **命运编织机** | 后台自动比对、挖连接的那一层。用来产出候选隧道/印记，不靠用户手动画。 |
| **时空潜望镜** | 扫视 + 缩放这套操作手感。用来在复杂图里「转着看、盯着看」。 |
| **印记档案** | 存连接元数据的库（谁连谁、哪一段、什么类型）。用来持久化，刷新页面连接还在。 |

> 记不住术语也没关系：整件事就三步——**有页 → 发现页与页之间哪几段相关 → 在空间里画出来让人转着看**。

### 二、 功能模块分类 (Product Architecture)

我们将专利中的技术组件映射为「非线性自传」的四大核心板块：

#### 1. 命运编织机 (The Loom - 数据处理层)
*   **对应专利**: 内容比对与连接发现算法 (Abstract & Fig. 7)。
*   **功能**: 自动扫描用户的“记忆碎片”（数据页面），识别出哪些段落是被“复用”的（Transclusion），或者存在强关联（Flink）。
*   **落地关键**: 需实现高效的文本指纹比对（如 SimHash 或专利提到的 Permascroll 坐标定位）。

#### 2. 灵魂地图 (Soul Map - 可视化层)
*   **对应专利**: CVS (Connection Visualization System)。
*   **功能**: 将枯燥的数据关系转化为直观的空间图形。不仅仅是列表，而是展示“此刻”与“彼刻”的空间相对位置。
*   **落地关键**: 必须支持 **Stand-off (分离视图)** 和 **Overlay (叠加视图)** 的切换。

#### 3. 时空潜望镜 (Periscope - 交互层)
*   **对应专利**: Sweeping (扫视) & Zooming (缩放)。
*   **功能**: 允许用户在复杂的连接网络中移动视角（Sweeping），像拿在手里的全息投影一样旋转观察；或者聚焦某一条具体的连接线（Zooming）。

#### 4. 印记档案 (Imprint Archive - 存储层)
*   **对应专利**: Strands (串) & Flinks 结构 (Fig. 6)。
*   **功能**: 存储连接的元数据。不仅是“A链接到B”，而是“A的第几行第几个字”链接到了“B的哪个位置”，以及这种连接的性质（是引用？是反驳？还是雷同？）。

### 三、 工程实现方案 (Implementation Details)

#### 1. 数据模型 (Data Model)
依据 **Fig. 6A-C**，我们不能只存 URL，必须建立以下结构：
*   **Node (节点)**: 对应 Data Page。需包含 `content_id`, `source_url`, `rendered_text`。
*   **Strand (串)**: 一个逻辑上的分组容器（例如“童年回忆”这一组连接）。
*   **Flink (前向链接)**: 核心实体。
    *   `type`: `dash` (虚线/弱相关), `pointer` (指针/强引用), `resemblance` (相似), `disagreement` (反驳)。
    *   `from_location`: 起点 (Page ID + Start Offset + End Offset)。
    *   `to_location`: 终点 (同上)。
    *   `corner_points`: 用于绘制的矢量坐标点数组（专利 Fig. 8 提到的关键点）。

#### 2. 前后端边界 (Boundary)
*   **后端 (Heavy Lifting)**:
    *   负责 **Transclusion Detection (包含检测)**: 当用户上传新的一页“自传”时，后台跑批任务，与历史所有页面进行文本切片比对，生成 Flink 候选集。
    *   输出 JSON 格式的拓扑结构数据。
*   **前端 (Rendering)**:
    *   接收拓扑数据，计算 **Layout (布局)**。
    *   实现 **Sweeping (扫视)**: 监听鼠标/触摸拖拽事件，实时更新 Camera 矩阵或 DOM Transform。
    *   绘制连接线: 使用 SVG Path 或 Canvas/WebGL 绘制 Bezier 曲线连接两个文本区域。

### 四、 前端 3D / 空间可视化深度展开

专利中 **Fig. 1 到 Fig. 5** 展示了一个从 2D 向 3D 进化的过程，这对前端挑战极大：

#### 1. 视觉隐喻：隧道与星座
*   **当前页 (Current Page)**: 始终作为“锚点”，通常位于视觉中心或左侧（Fig. 1, Fig. 2）。
*   **到达页 (Arrival Page)**: 浮动在周围空间。根据专利描述，它们可以是 **Stand-off (分离)** 的，也可以是部分透明的 **Overlay (叠加)**。
*   **连接线 (Tunnels)**:
    *   专利强调连接线不是简单的直线，而是有 **Span (跨度)** 的区域（Fig. 8a, 8b）。
    *   **实现建议**: 使用 Three.js 的 `ShaderMaterial` 或 Canvas 2D 的 `bezierCurveTo`。连接线的粗细应代表内容的“权重”或“相似度”。

#### 2. 关键交互：Sweeping (扫视)
*   **定义**: 改变观察角度，使得原本重叠的连接线分开，看清走向（Fig. 3, Fig. 4）。
*   **技术难点**: **Z-fighting (深度冲突)** 和 **Occlusion (遮挡)**。
    *   当几百条连接线汇聚时，如何保证用户能看清楚？
    *   **解决方案**: 引入专利提到的 **Corner-points (角点)** 控制。动态计算贝塞尔曲线的控制点，使线条在 3D 空间中呈“放射状”散开，而非乱成一团。

#### 3. 文本对齐 (Text Alignment)
*   专利 Fig. 5 显示了文本的具体对齐方式。前端需要实现一个 **Virtual Viewport (虚拟视口)**，能够截取长文本的中间某一段（Start/End offset），并将其渲染在 3D 空间的特定平面上。

### 六、 把关清单 (Checklist)

#### ✅ 第一阶段：必做 (MVP - Minimum Viable Product)
1.  **基础并排视图 (Fig. 1)**: 实现左右或主副屏结构，左边是 Current Page，右边是 Arrival Page。
2.  **高亮与连线**: 能够选中一段文字，并在另一侧文档的高亮区域间画一条线（SVG 即可）。
3.  **基础 Flink 数据结构**: 后端能记录 `from` 和 `to` 的字符偏移量 (Offset)。

#### ⚠️ 第二阶段：高风险 (High Risk / High Reward)
1.  **自动化 Transclusion 检测**: 不要试图一开始就做完美的 AI 语义理解。先用 **N-gram** 或 **编辑距离** 做字符串匹配。专利里也是基于 Permascroll (永久滚动条/地址) 的精确匹配思路。
2.  **3D 性能优化**: 如果使用 WebGL，必须对文本纹理做 **Atlas (图集合并)** 处理，否则 Draw Call 会爆掉。
3.  **Sweeping 交互逻辑**: 这是最容易做成“晕眩 3D”的功能。**把关点**：限制旋转角度（如 Y 轴 -45° 到 +45°），不要让用户彻底转到文字背面去。

#### ❌ 第三阶段：暂不做 (Do Not Do Yet)
1.  **复杂的 3D 物理碰撞**: 专利提到了解决 Overlaps (重叠)，但在 MVP 阶段，直接隐藏被遮挡的线或降低透明度即可，不需要物理引擎计算排斥力。
2.  **实时流式比对**: 不要在用户打字时就实时画线。应当是“保存/确认”后触发异步任务，否则前端会卡死。
3.  **Disagreement (反驳) 的自动判定**: 这属于 NLP 高级能力，现阶段仅支持用户手动标记“这条线代表矛盾”。

### 总结
该专利提供了一套非常完整的**“基于位置的文本超链接可视化”**方案。对于「非线性自传」而言，这不仅仅是技术参考，更是**产品哲学的核心**：**记忆不是线性的列表，而是由无数个“印记”(Transclusion) 和“隧道”(Flink) 编织而成的 3D 网络结构。**

**下一步行动**: 先搭建 **Strand/Flink 的 JSON Schema**，并实现一个基于 **Canvas 2D** 的原型，重点攻克“长文本截取渲染”和“贝塞尔曲线动态避让”这两个具体技术点。
